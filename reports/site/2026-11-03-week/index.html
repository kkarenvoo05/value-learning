Frozen encoders: where does π₀.₅'s value noise come from? (P1, P1b, P1c)

2026-11-02 to 2026-11-03 · LIBERO libero_10 task 8 ("put both moka pots on the stove") · status: P1c step 2 queued

Question

π₀.₅ value models give a jittery within-episode V (advantage-label SNR 0.07 for B, vs 0.25–0.27 for the fine-tuned ResNet). Is the noise already in π₀.₅'s image features, added by its language-model (LLM) layers, or added by fine-tuning?

Setup

  • Frames: every 4th frame of the fixed + fresh table (/iris/u/ankile/karenvo/libero/tables/moka_fixed_fresh), 117,993 frames, both cameras. Val = the 10 value-val init states (120 episodes, 13,944 frames); inner = 5 train states (early stopping). Fit set varies by row (below).
  • Encoders [ours]: resnet_in (ImageNet ResNet-18), siglip_pi05 (π₀.₅'s SigLIP, mean of 256 tokens), siglip_web (timm SigLIP So400m/14 webli), resnet_ft / siglip_pi05_ft (fine-tuned value-model backbones 18237895 / 18269859), llm_final (frozen π₀.₅ final-layer prefix hidden states, image-token means), llm_v{1,5,9,13,17} (per-layer attention values V, 256-d), *_pca256 (PCA to 256-d per camera).
  • Measure: the same MLP value head (scripts/libero_head_swap.py, 3 seeds) on each frozen feature set, scored by score(); main metric head SNR 2 s (within-episode change in V, success minus failure, time-matched, over its noise). Also a linear pot-on-stove probe and robot-state R².
  • Code: scripts/libero_frozen_encoders.py (extract / analyze, --fit-subset, --tag), scripts/libero_p1b_prepare.py, scripts/libero_p1c_pca.py.
  • Data files here: p1_fit825.json, p1b_fit375fixed.json, p1c_pca256.json, p1c_fit375fresh.json, p1c_fit375fixed_p1dir.json (copies of analysis*.json from /iris/u/ankile/karenvo/libero/features/).

Verdict

  • Observed: frozen π₀.₅ SigLIP is as steady as an ImageNet ResNet at 825 episodes and better than web SigLIP. Robot (VLA) training did not make the vision features noisy.
  • Observed: two separate drops, each about halving head SNR: the frozen LLM layers (0.122 → 0.059) and SigLIP fine-tuning (0.172 → 0.084 at 825; 0.122 → 0.078 at 375).
  • Observed: at equal size, fresh layouts beat fixed layouts by a lot (SigLIP 0.122 → 0.194); adding fixed episodes to fresh lowers SNR. SigLIP is more layout-sensitive than the ResNet.
  • Interpretation: the fixed-layout fit invites a layout shortcut. The 256-d projection explains ~0.007 of the layer-1 drop; ~0.02 remains (≈1.6 sd), not decisive. Gentler SigLIP fine-tuning alone cannot fix B, whose value reads the LLM prefix.

Caveats

  • One fine-tuned SigLIP checkpoint at one learning rate.
  • V rows are a learned 256-d projection, not hidden states (P1c step 2 fixes this).
  • P1b's LLM rows exist only on the 375-fixed fit set, the shortcut-prone one.
  • Retracted along the way: "frozen SigLIP needs more data" (it needs more layouts).
